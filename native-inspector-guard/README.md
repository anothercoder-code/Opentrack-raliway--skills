# OpenTrack Inspector Guard

This is an independent, optional English-only x86 DLL and console launcher for the stock OpenTrack 1.7 Windows process. It does not replace OpenTrack, modify its EXE, or contain the commercial EXE. It does not include OTUndo, translation, IME or history features.

Current acceptance: **compiled and headless regression passed; native GUI acceptance is pending**. This iteration did not start OpenTrack, execute its functions, load its PE as a module, attach a process, inject a live application, or operate its UI. Do not treat this artifact as a completed release certification.

## Entry points

`out/ot-inspector-guard.exe` with no arguments prints help and exits.

`out/ot-inspector-guard.exe --check <absolute-path-to-OpenTrack.exe>` reads the PE header and SHA-256 as file bytes. It does not load the guard DLL or launch/attach OpenTrack. A supported stock file returns zero; a malformed, truncated or mismatched file is rejected. No runtime readiness or GUI behavior is proved by this command.

`out/ot-inspector-guard.exe --launch <absolute-path-to-OpenTrack.exe>` is the explicit **future live validation** entry. It refuses an existing `OpenTrack.exe`, creates its own new child suspended, registers an independent WH_GETMESSAGE hook on only the returned child thread, and then resumes that child with normal window visibility. Before Ready, the hook filters queued keyboard messages, client-area mouse/wheel messages and queued `WM_CLOSE`. Non-client, system-command and synchronous messages are outside that filter; this is not a complete UI input barrier. A nonce-scoped Ready/Failed handshake must complete within 30 seconds. Any pre-Ready failure stops only the child created by that invocation. There is no attach/PID option and no OpenProcess/CreateRemoteThread path. The launcher temporarily adjusts only its own child environment. It does not change system settings or existing OTUndo launchers. This entry was not executed during the static-only iteration, and native startup interaction remains unverified.

## Guard contract

`contract.json` and `src/contract.inc` bind the original SHA-256 `f1274d5c03ac7fe07196c999eb088e6de7414a1da55b0276d3956513c866f104`, PE32/x86 headers, 32 method addresses/type encodings/16-byte prefixes, 25 class addresses/instance sizes and 21 ivar names/types/offsets. They were generated by reading the PE as bytes and recovered metadata, without executing the original PE. The three installed OpenStep DLLs also have fixed file SHA-256 gates in `guard.c`; only the classic runtime exports actually present in that runtime are used.

Installation waits for class relationship linking on the native UI thread. A missing API, file fingerprint, class, ivar, method address, encoding or ABI rejects activation before any method replacement. Inspector receives its own `dealloc` override through classic `class_addMethods`; the inherited NSObject method table is never modified. Other hooks replace only methods with the exact expected original IMP and encoding. The guard DLL is pinned before reporting Ready.

Inspector selection and `inspectList` are cleared before `inspector:` can call `orderFront`, before `update:` including its active-panel-nil early return, and before `updateSignal:`. The selected pointer is never messaged or retained merely because it is non-null. A live document list, owning document, document view, view array and model array establish identity membership first. The weak `documentView` window delegate is additionally proved through `NSApplication.windows` and the window's strongly owned `contentView`/`subviews` tree before that candidate is retained or read. Both the model/view reciprocal link and document/view link must agree. The verified document, document view, view and model are then pinned together while native callbacks execute, and only current selection dependencies remain pinned afterwards.

Table callbacks reject poison/unowned selection addresses and validate every multi-selection view by identity before calling the original datasource. A requested row must also be below the current original datasource row count. Synchronous table reentry during Inspector setup is suppressed. After an outermost verified operation finishes, active-panel tables receive a stable `reloadData` so suppressed callbacks do not leave cached empty rows. Each table outlet must first appear in its panel's strongly owned view tree; a stale outlet is never messaged to test it. Inspector close, document close, graphic-view deletion, document/document-view deallocation and every recovered model/view descendant deallocation invalidate references. An epoch and per-Inspector generation prevent old callbacks from restoring pointers after a nested close/delete/deallocation. Pending and persistent pin leases are both tracked. An explicit native `dealloc` that bypasses retain ownership poisons the affected leases; those object references are abandoned until process exit rather than released through a freed pointer. The empty lease container is still reclaimed.

The capture limits are 64 documents, 4096 model/view pairs, 16 Inspectors and 64 simultaneous leases, with bounded view-tree traversal. An exceeded limit clears/denies that Inspector operation. The guard is scoped to the recovered UI-thread model. An unexpected non-UI deallocation/document-close callback fails closed by stopping the current guarded process with exit code 92 before mutating shared state or messaging AppKit. This fail-stop path was tested only in the project's own console mock. Real startup, cross-document editing, close/reopen and simulation interactions still require native GUI testing.

## Build and offline regression

Run `build.cmd` with MSVC x86 installed. `OT_IG_SDK` may point to Windows Kits/10; the default reuses the SDK already available in the local OpenTrack workspace. No OpenTrack process is used for compilation. `tools/make_contract.py` is a maintainer tool with the local stock PE and metadata-bank paths; it reads bytes only.

Run `test.cmd`. It executes only the project's own console test executables and the launcher's default/`--check` branches. `tests/adapter_tests.c` includes the real adapter and substitutes an owned synthetic x86 Objective-C graph; it never loads the original runtime or PE. Its 11 cases cover clear-before-orderFront, stable row/cell refresh after suppressed reentry, out-of-range rows, the active-panel-nil return, stale selected/argument pointers, dependency pinning, synchronous table reentry, invalidation epochs, pending explicit deallocation, Inspector deallocation during callback, stale weak document-view delegates, stale table outlets and broken reciprocal links. Six policy tests additionally cover slot reuse, nested deallocation during release and poisoned-lease reclamation. A separate mock child tests the non-UI fail-stop exit. Nine offline launcher cases cover supported stock bytes and malformed/truncated/mismatched inputs.

`../evidence/native-guard-summary.json` records exact results and binary hashes. Independent static reviewers additionally check the raw original PE metadata and adversarial policy cases. These results do not establish native GUI or simulation acceptance.
