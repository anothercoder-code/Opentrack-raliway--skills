# 原版随机延误批次的到发与占用统计

先用[原版仿真任务](native-simulation-jobs.md)对同一工程提交至少两个不同的
原版随机延误编号（1–200）。可加入编号 0 作为对照。逐车验收给出实际始发站和终点。
若需区分某一区域的占用，为该区域配置并选中[原生占用组](native-occupation-groups.md)。

任务结束后使用 `opentrack_summarize_native_delay_batch`。输入示例

```json
{
  "job_directory": "OTAI/workspaces/RobustnessBatch",
  "latest_arrival_s": 180,
  "resources": [
    {"document": "J22", "name": "J22_Safety23"}
  ]
}
```

```powershell
python -X utf8 -B scripts/ot.py --root D:/RailWork --profile generation call opentrack_summarize_native_delay_batch --args-file D:/RailWork/batch-summary.json
```

`latest_arrival_s` 是接受的最大终到晚点，按原版记录的实际到达减计划到达计算。工具核对原版进程、
冻结输入散列、原版协议中实际使用的场景编号和结果散列，并从任务的源快照复现第一轮的完整原版输入。
同一批只允许场景编号和工程搬移路径造成差异。
任务绑定外部 OTD 规则时，编号 0 和所有编号场景须通过同一规则包的哈希、运行副本与启动参数核验。 [原版 OTD 规则绑定](dispatching-rules-otd.md)
逐轮保留完成情况、始发延误、终到延误和占用。通过整轮逐车验收的随机运行才进入汇总，编号 0 单独列在
逐轮数据里。缺少计划到发时刻的已终到车次会单独列出。每项返回有效样本数、最小值、最大值、均值、
中位数和按最近秩定义的第 95 百分位。

占用表同时显示原版 `OT_OccStatistics.txt` 的次数及预留百分比，以及从配对的
`SR/SO/EO/ER` 时钟计算的该区段预留、物理占用的累计秒数。每轮先取同区段各列车时段的并集，
再跨运行相加。同一时间多个成员的占用只计一次。缺失原版统计或时钟配对不全时保留缺失值和
有效样本数。汇总会核对各随机轮使用的原版占用时段相同。原版自身报表的预留比例与基于整段运行窗口的时间测量各有口径。

编号 1–200 对应原版的随机延误方案。批次为每个编号启动独立原版进程，统计基于这些进程的封存实绩。
原版会话内的共享累计表及随机样本的代表性需另行验收。

## 核对原版小数延误并计算场景级区间

在同一汇总请求加上 `original_delay_plots: true`，并在原版运行任务中启用延误统计输出。
该模式按原版协议列出的全部车次核对 `OT_Delay.delall`、`.delallarr`、`.delalldep`、
`.delbegin`、`.delend`、`.delavg`、`.delmax`、`.dellaststop` 和 `.delact` 的签封输出。
站码由冻结 `.stations` 对应到各车次 `.tt` 的车站名；原版延误图时钟不含日号，通过匹配的
`.tt` 保留绝对秒数。无法唯一对应同一打印时刻的不同延误值时拒绝自动匹配。

原版图表打印到 0.1 s，整秒时刻表差值有时会给出不同的准点结论。原版平均延误和最大延误
由带计划时刻的到达与出发计算。最大延误的下限为零，原版 `.delact` 的空车次零值保留为占位。
可核对最后有计划时间的事件与实际终到是否相同。原版图表的阈值统计以所打印的小数值为准。

`confidence_level` 默认为 0.95。默认区间采用 Wilson 方法，每个编号的场景单独计一次，
整轮所有指定车次均在阈值内才记为整轮通过。区间成立的条件是这些场景可视为独立且有代表的抽样。
存在未核对的随机场景或终点时仅报告观测值。完整枚举原版 1–200 的编号时报告这组固定场景的
实测比例。编号 0 仍单独列在逐轮数据中。

九站网的原版验证含 8 个随机编号和 1 个零号对照，每个编号各运行 33 班车。在 108 s 阈值下，
H2E2 的 8 个原版终到小数延误为 108.6–108.8 s，整秒时刻表均为 108 s。
小数口径下 0/8 整轮通过，整秒口径为 8/8。该结论使用封存样本和明确的门槛。
