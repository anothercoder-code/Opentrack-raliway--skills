# Full 与 Basic 的能力范围

完整版 full1 与基础版 basic2 使用相同的配套协议 `0.33.1-zeroaccept1` 和 Python 3.13.x。
两版均先满足[有效原版完整版软件授权](software-authorization.md)，再开展相关业务。

## 按能力区分版本

| 能力类别 | Full full1 | Basic basic2 |
|---|---|---|
| 基础检查、字段和引用验证 | 保留 | 保留允许接口 |
| 从零工程与一站一文件 | 按需求选择、组合已实现接口和适合的原版工作流 | 当前公开初始化流程限2–3站、单向单车、末站停 |
| 复杂站场与路网设计 | 按实际需求组织多股道、咽喉、道岔、方向、联络和资源关系 | 不提供复杂拓扑自动构造及高级变更入口 |
| 多车运营、冲突、跟随和故障处理 | 按各接口合同组织计划与原版审计 | 保留基础单车联程检查，不提供多车/故障构造 |
| 车辆、时刻表、线路和批量编辑 | 提供已实现的进阶数据接口 | 仅有限参数与计划时刻预览，不直接保存标量修改 |
| 原版保存重载、实操或用户指导 | 保留 | 在基础流程内保留 |
| 软件运行图和原生导出 | 真实轨迹、Corridor和原生EPS/TIFF工作流；具体辅助脚本范围单独说明 | 不提供原生导出桥 |
| 函数资料和进阶交换 | 提供实际实现的资料及接口，缺项如实说明 | 不暴露 |
| 数据工具入口 | 以当前 `tools --profile=all` 清单为准，含 8 个已封存旧几何入口 | 21项 |

三纵三横、九站、八股道站场等是**复杂设计举例**，不是必须选择的特殊功能、固定规格或
完整版的整体能力上限。复杂设计由用户需求决定，按[设计工作流](complex-design-workflow.md)
组织实现。不要把其他线网或站型强行改成这些例子，也不要因为名称不相同就拒绝同类任务。

## 具体生成器与案例仍有自己的边界

便捷生成器可以保持固定合同：例如线性初始化器2–12站、三站八股道示例、九站网格示例。
这些数值约束**该入口**；其他设计应组合适当接口、采用原版操作或在授权范围内补齐适配。
不能直接解除某个生成器的校验后宣称支持任意设计，也不能把旧案例的成功当作新工程验收。
本次H2三站五车次导图是原生导出实例，不把软件可选择的Corridor限定为H2。

基础版2–3站限制来自本版明确的产品策略，不是原版软件限制或通用铁路设计原则。
CLI/MCP/HTTP共用Basic白名单；不能换后端绕过。复杂能力的裁剪按能力类别执行，不按
“三纵三横”或某个模板名称执行。两版都保留输入安全、英语原版字段、前态、真实验收与授权。

完整版表示完整维护的Skill能力集合，不表示原版全部176项功能等价、任意拓扑均已支持、
实车标定或铁路安全认证。原版商业程序、运行库、私有供体和许可材料均不随包提供。
历史basic1保留追溯；它曾包含较广接口，不能据此推断basic2当前能力。

接口数量只统计登记，不代表全部当前可用或原版已验收；必须查看BLOCKED标记、实际schema、依赖和主机条件。封存入口不应通过修改标志解锁。
