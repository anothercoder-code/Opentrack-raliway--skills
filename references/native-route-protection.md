# 原版跨图档慢行区与释放边界核验

`opentrack_verify_native_route_protection` 对已封存的一次原版运行复核同一车次上的跨图档主进路。运行凭据须绑定原版程序、工程和输出散列。测试案例可在集中验收请求中附上可选的 `route_protection`。干跑冷读冻结项目及所需输出配置，原版完程并校验输出散列后执行事后检查。

```powershell
python scripts/ot.py --root D:/opentrack --profile generation call opentrack_verify_native_route_protection --args-file D:/opentrack/OTAI/workspaces/ReadingP9CrossingSlowZoneM14Evidence_20261123/native-route-protection-request.json
```

请求提供原版输出目录、证据目录、`course_outcome` 和 `protection`。每个被选主进路按图档、名称、阵列 ID 和有向起点标识，需明确跨档慢行区两端、合并后的完整有序释放组和唯一信号档位码。车次须只绑定一条 Itinerary，每个主进路各通过一次图档边界。

- 原版加载后以续段的非空慢行端覆盖主段暂存值，并按序追加释放组。工具将这些有向 End 投影到冻结走行轴。慢行区起点、连接处及终点报告实际原始车头样本，进路授权须早于跨界样本区间。对应反编译函数的仓库外原始分析文件
- `.sigpos` 的主信号档位列来自进路的可用信号档位列表。固定公制档位另用同一原始时间的 `.vt` 速度和 `.st1` 车头位置，检查连接器两侧有多处实际达限样本，允许原版输出舍入误差。唯一档位码为 0 时报告原版 `TS` 图例和实测速度峰值，速度模式为 `no_fixed_signal_cap_reviewed`。档位图例与本次速度观测分开输出。对应反编译函数的仓库外原始分析文件
- `.step2` 必须在每个释放组的线路中间锚点出现唯一释放前沿，前沿还需有先行授权，列车车头样本须到达其下游。未产生进路释放前沿的车次首尾锚点以存档身份输出。原版释放时刻可落在两个车头样本之间，结果保留样本区间。

封存的 Reading M14 在 2,025–3,425 m 和 3,425–4,825 m 两条跨档进路上，分区实测峰值均为 40 km/h。原版释放到 2,525、3,425、3,625、4,325 m 的时刻分别为 37584.02、37664.70、37678.63、37741.38 秒。4,825 m 是车次终点锚点。同几何的历史无慢行区对照在插入轨实测 75 km/h。对应项目的原版运行记录与本仓库分开存档。

新的 RPROT01 反向改造候选已冷读核对慢行区 685–1,525 m、跨界位置 925 m、内部释放锚点 685 与 925 m。冻结进路保存的是档位码 0，这次候选范围为起止位置、跨档通过、原版图例、实测速度记录和真实释放前沿。改造后的实绩留待最终原版验收。对应项目的原版运行记录与本仓库分开存档。
