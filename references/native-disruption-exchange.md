# 原版事件文本交换

`opentrack_import_native_incident_text` 读取英文 OpenTrack 原版事件 TSV。
它按 13、19、26 或 31 列读取，保留空列，再按所选 `.run` 核对车次、图档、股道或进路身份。
提交原始文本的 SHA-256、原工程绑定和新增目标 `.courses`，即可把事件追加到原生车次目录。
原有事件和事件集仍随目录保留。先预览时可以检查新增名称和目标身份。

现行写入覆盖列车限速、信号与轨段封锁、进路和径路限速、轨段组、信号停车、牵引力和区间事件。
限速支持原版「仅作用于车头」位。原版事件备注、概率、周期、开始和持续时间分布
由相应列保留。分布必须指向这份工程已存在且可验证的表。

`opentrack_export_native_incident_text` 接受 SHA-256 绑定的原生 `.courses`，生成新
`.txt`。非周期牵引力或公里范围字段使用原版可重读的 26 列布局。原版的 31 列导入器
读取周期字段时跳过牵引力和公里范围列。若这些值同时有效，工具返回字段缺失错误。
信号追踪间隔、列车功率和「停车等待」的等待秒数存在原生档案字段，原版 TSV 缺少相应列。
用 `opentrack_preview_infrastructure_incidents` 直接写入这些字段。只有零秒等待可通过文本来回传递。

## 公里标和进路范围

提交 `spec.incidents` 时可选以下类型。公里值为原版十进制字符串，例如 `"56.600"`。

| `type` | 范围字段 | 额外字段 |
| --- | --- | --- |
| `position_speed` | `line_id`、`track_id`、`begin_km`、`end_km` | `reduced_speed_kmh`，可选 `head_only` |
| `position_blockage` | 同上 | 影响选中的完整轨段及两个运行方向 |
| `position_stop_wait` | 同上 | `wait_time_s`，可选 `head_only` |
| `route_span_speed` | `begin_route`、`end_route`、`begin_offset_km`、`end_offset_km` | `reduced_speed_kmh`，可选 `course_id` 和 `head_only` |

空线路名或股道名匹配全部相应值。公里标区间使用选定工程的保存端点公里标和轨段方向。
升序与降序用于区分行车方向，相同的起终公里标可指定一个点。检查回执 `span_targets`
中的轨段，并确认实际列车经过它们。进路相对范围使用唯一的原生进路名，每个偏移分别
从对应进路的起点算起。修改带范围事件的进路前，需先处理对应事件引用。

Reading 的原版实跑检验了四种范围事件。公里标限速把区间实际速度从 80 降到 30 km/h。
公里标封锁让列车在站台出站信号前等待至 10:27:10。停车等待使列车在距始发 856 m
处零速停留 35 秒。进路相对限速把指定偏移区间实际速度从 80 降到 25 km/h。
这四个工程里的列车均完成站台停靠并终到。

原版 1.7.6 对同一案例的「仅作用于车头」公里标限速和停车等待出现过 `0xDEAD`
退出。整列车方式通过上述实跑。起止公里标相等的停车等待在该原版案例中只有触发日志，
未停车。需要模拟有方向的点停车时可提交窄范围，并验收零速位置和等待秒数。

导入完成后，另按 `.run` 的 `Incident` 选择对应事件并用[原版仿真任务](native-simulation-jobs.md)
验证实际触发和结束。事件落盘、写入正确选择和实际触发分别留存证据。

## 车载性能与信号事件的实际效果

在 Reading 的原版对照组中，RDG09 出站牵引力峰值为 280 kN。车次专属事件在
10:24:50 至 10:26:10 把牵引力峰值降至 140 kN，结束后恢复到 280 kN。同一时
窗的 2,000 kW 机械功率限制实际生效，结束后恢复。使用 `.tsvP` 的移动样本核验。

Reading 出站信号的 42 秒停车事件使车次在原版于 10:25:43 发车，比对照组晚
43 秒。九站工程在 J22 进站主信号写入 160 秒追踪间隔，后车的对应进路预留
与前车相隔 160.03 秒。对照组为 97.67 秒，事件组 33 列车均终到。原版
`.step1` 的进路预留时刻与 `.st1` 的实际通过时刻分别核对。

同时检查事件起止、物理峰值和预留间隔的方法见[原版结果核验](native-run-evaluation.md)。

### 从冻结工程对照实际限速、牵引、功率和信号停车

`opentrack_compare_native_incident_effect` 接受 `control` 与 `incident` 两组已完成并封存的
原版任务路径，以及事件 `name` 和同一趟车的 `course` 完程条件。支持完整 Path 限速、指定车次的
牵引力系数与功率限制。原生 `.courses` 给出事件目标、阈值、日偏移和开始结束时刻。

对照只改变这一原生事件及其 `.run` 激活项。接口校对冻结车辆、时刻表、图档和其他运行设置，
并查验原版运行协议、两条激活消息和事件前物理样本。Path 按图档、拥有方向端和阵列 ID 定位。
接口用原版 `.tsvP` 查验事件期内两个算例共同走过的那段里程；牵引力在相同打印速度下对比。
结果保留原始活动时钟、峰值样本和文件散列。

Reading 封存数据中，同图档 Path 对照实测峰值由 79 降至 45 km/h。乘以 0.5 的牵引力例在
87 个相同打印速度上测得 280→140 kN。2000 kW 功率申明的实测活动峰值约 2000 kW，
结束后约 6169 kW。接口仅核对同时有原版控制与完整输出的确定性事件。

固定时长的 `signal_stop` 当前核验与原计划车站停车位置重合的主信号。事件及停车概率都须为
100%，提供明确的 `stop_duration_s`。两组均使用同一条保存的定向交路。在两组运行中启用
原版信号位置、进路预留、速度、位移、时刻表、消息与车次统计输出，并保留各自封存的 `evidence`。
同一份请求无需额外指定信号，工具从冻结 Incident12 的图档和信号 ID 回读方向 End，沿图档
计算信号位置，再用 `.sigpos`、`.step1`、`.vt` 和 `.st1` 核对。预留由原版的阶梯变化定位。
仅在两案的事件前样本相同、停车的开始一致、原版告警指向同一列车和信号，并在事件仍有效时
实际过信号恢复走行的情况下，才核对额外停驶与保存的时长是否一致。

```powershell
python scripts/ot.py --root D:/RailWork --profile generation call opentrack_compare_native_incident_effect --args-file D:/RailWork/signal-stop-effect.json
```

Reading P9 封存对照中，事件设置 42 秒。原版在距始发 2,025 米的 `S:RDG:8` 前，控制组
停驶 120.00 秒，事件组停驶 162.23 秒。原版 37,543.14 仿真秒重新建立出站预留，随后恢复走行，
事件到 10:28:40 才结束。实际发车从 10:25:00 变为 10:25:43，终到从 10:27:14 变为
10:27:56。两组允许的唯一额外配置差异是原版的 `Output Time/Dist./Speed/Power` 遥测日志开关，
它的变化单独记录在 `physics_log_option_difference`。报告仍要求其余运行参数和冻结输入一致。

```powershell
python -X utf8 -B scripts/ot.py --root D:/RailWork --profile all call opentrack_compare_native_incident_effect --args-file D:/RailWork/incident-effect.json
```
