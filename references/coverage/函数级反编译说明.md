## 直接使用

先用 `opentrack_read_function` 检索或读取函数，再阅读相关被调用函数。`query` 或只填类名返回目录；确切 selector／入口地址返回函数正文，`offset` 和 `limit` 控制分页。

```json
{"class_name":"OTEngineController","selector":"convertArrayOfImportedPoints","limit":100}
```

```json
{"address":"0x4d1bb8","offset":0,"limit":100}
```

本机离线命令：

```powershell
py -3.13 -B -X utf8 D:/opentrack/OTUndo/tools/read_decompiled_function.py --class-name OTEngineController --selector convertArrayOfImportedPoints
```

## 如何判断结果是否可用

先确认循环、分支和被调用函数存在，再核对 Objective-C 接收对象、参数数量、浮点返回和结构体 ABI。通用 `objc_msgSend` 声明可能让反编译器省略真实实参；可变参数输出还需要根据格式字符串恢复参数。本次对 Engine 相关函数加了原生类型和调用点修正。例如，曲线导出已能显示当前点、下一点索引及实际写入的速度和力；H 标志的传递方向也已经明确。

完整性校验核对全部函数文件哈希、入口映射和关键函数控制流。读取接口再次核对 ZIP、索引、哈希清单及所选 C 文件。初始错误标记 `objc_msgSend` 不返回造成的截断输出已经拒绝，不作为实现依据。原先依赖旧研究目录的类清单范围有限，本次从原始 PE 的 class、metaclass、category 结构重新扫描。

若某一调用仍存在疑问，针对该处核对汇编；然后用原始存档样本验证数据表示，用实际 MCP 协议验证接口。可阅读函数不等于该原生业务命令已经完整复刻。对照表把函数读取、保存数据子集和原生方法调用分开，原生方法调用未开放。
