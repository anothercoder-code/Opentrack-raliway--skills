# Wave11: paired StationVertex creation and static planned visits

This supersedes the geographic station assumptions of wave10, not the documented
limits on dynamics, stopping, physical fleet, complete global options or runtime.
The existing tool and strict nine-source input schema remain unchanged.

For each selected current OTEndModel v7 (EndRef vertex/side), expand its reciprocal
related pair. Both members must be actual unique same-document ordinary type1
Ends in fresh generation. The pair is owned by exactly one requested station sign.
Selecting the other half or both halves is equivalent; selecting the related half
under another sign is a conflict, not a second independent station.

Create one current StationModel1 and Station3 record per station sign. Write the
same actual StationModel reference to End group12 on both halves; write documented
StationVertex type2 in group20 on both. Inspect both halves' incoming owners before
mutation. No Connector subclass is accepted; no invented no-wye rule applies.
Do not alter class, pair IDs, geometry, signals, routes, Path counters, opaque
header or other fields. Removing the new StationModels and restoring group12=nil
and group20=1 must exactly recover original bytes.

Readback and operations parsing require reciprocal pairs, exact type1/no station
or type2/same actual StationModel on BOTH halves, unique station identities and
catalog closure. Arbitrary type3 is not accepted just because the native !=1
predicate would return true. An old type1+Station association fails this profile.

Visit order is derived from actual selected Dest/Path/Route End occurrences and
the documented type2 native station predicate, never only from supplied JSON plan.
Related halves represent one logical vertex: count only the directional End actually
traversed. Deduplicate consecutive Route/Path shared boundaries, not repeated laps.
Within one Path, two distinct logical reference vertices for one station sign are
ambiguous and refused. A→B→A→B→A over finite repeated Paths remains five visits.

The input timing_point=true preserves the pre-existing catalog timing flag choice;
it is NOT the geographic StationVertex predicate. TT flags remain2: stop=false,
timing=true. Pass arrivals equal departures, dwell0, actual time placeholders unset.
No stop area, platform, turnround, Connection circulation or dynamic feasibility
is generated by this correction. Planned speed lower bounds and margins remain
necessary static checks only. The minimal optional run binds archive paths and
creates the empty output directory, but complete_runtime_configuration=false and
execution_root_verified=false remain mandatory.

Evidence: OTAI/artifacts/wave11-evidence/station-vertex/CONTRACT.md and its hashed
Ghidra C with verified Objective-C metadata. This is inferred native-function
semantics, not vendor source or execution evidence. Current user scope is static
archive/function verification only; do not launch the original application.

Scope clarification: type1 Ends with Station associations can be valid native
station-area members. They are refused here only in this point-only generated
StationVertex profile, not diagnosed as universally corrupt native archives. A
future stopping-area profile may legitimately mix type1 region members with type2
reference vertices; that profile is not implemented or accepted by this pipeline.

Reverse-direction oracle checks related-half identity and physical Edge adjacency;
it does not grant a reverse route authority or prove reverse signaling/interlocking.
