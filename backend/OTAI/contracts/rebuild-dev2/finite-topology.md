# Finite explicit topology — dev2

`opentrack_preview_finite_explicit_topology` creates new in-memory archives from explicit graph specifications, using two SHA-bound donors (Document4 header, class-shape archive). It does not edit the donor, existing projects or the user's three-by-three operating design. No archives are exported by the wrapper.

## Input and output contract

- Explicit 1–16 document names, each with its own vertices, edges and optional point stations; aggregate <=400 double vertices and <=800 edges. These are tool bounds, not original software limits.
- Topology inherits the validated current constructor: at most two edges on each half-vertex, unique endpoint pairs, explicit finite coordinates/length/speed data. Detector-enabled vertices remain outside this domain; raw track/loop/dlink profile remains 1/1/1.
- Point station sign/name, selected vertex/side, placement and timing-point flag are explicit. Both halves reference the generated StationModel. They do **not** define platform or stopping areas.
- A connector pair names exact document/vertex/side endpoints. Only unused nonstation ordinary half-ends are converted; each endpoint appears once. Cross-document pairs are reciprocal and saved as document basename plus exact local end ID. Internal connector mode is not exposed.
- Core returns document bytes and a combined station catalog. The typed wrapper returns file hashes/sizes, vertex/edge IDs and connector pairs, `saved=false`, `operating_ready=false`.
- Geometric crossings do not imply graph connections. Routes, Paths, Itineraries, train data, timetable and run configuration are not generated by this tool.

## Evidence and invariants

The implementation composes existing `zero_generation.topology.generate_network`, `zero_operations.station_binding.bind_stations` and `multi_document.core.Project` contracts. The first regenerates all graphic objects while preserving the donor header; the second validates paired station references; the third re-decodes the complete multi-document graph and checks reciprocal saved connector references.

Freshly re-read original01 static functions `OTConnModel.encodeWithCoder:` 0x4103dc and `initWithCoder:` 0x4102d8 corroborate the four appended values: dragFileName, blockTopo, blockEnd and internal flag; initialization forces ordinary stationEndType and clears runtime simBlockEnd. This does not reproduce GUI allocation/deletion history or establish native application loading.

After fresh serialization/reload, every connector is reverse-resolved. Removing only connector class/field additions must reproduce each preconnector graph byte-for-byte. The merged station catalog is freshly decoded with exact declared signs. Donor SHA is checked before use and donor files rechecked before returning the preview.

## Verification and requirement mapping

10 ordinary tests pass, including a three-document cyclic connector network with point stations, a finite branching graph, single document without edges, declared bound rejection, duplicate/unknown/occupied references and preview source preservation. One test uses restored original donor BJTU1 and shape bytes; nine use synthetic shape/header objects. None executes OpenTrack or proves operational safety.

Partial generation/read coverage: M2.1.2, M3.3, M3.3.1, M3.4, M3.5; point-station subset of M3.3.2, M3.7 and M3.7.4. No claim of full requirement completion. Existing-project modification and export are not provided by this interface. Dynamic behavior remains OpenTrack's responsibility.
